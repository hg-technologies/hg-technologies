## 🏗️ BuildSync

One of our core technology initiatives is **BuildSync**, an EPC automation platform designed to digitally connect project execution and operational workflows.

BuildSync focuses on three fundamental pillars:

### 👷 Man

Workforce, responsibility, approvals, accountability, and operational coordination.

### 📦 Material

Material requests, approvals, dispatch, weighment, quality inspection, receipt, procurement, and consumption tracking.

### 🚜 Machine

Equipment requests, approvals, allocation, acknowledgement, utilization, time logs, idle tracking, and deallocation.

The platform helps connect project sites, plants, engineering teams, management, and enterprise systems through structured digital workflows.

## 🔐 Security

Security is an important part of our development lifecycle.

* Never commit passwords, API keys, tokens, certificates, or credentials.
* Store environment-specific configurations securely.
* Use approved secret-management practices.
* Follow least-privilege access principles.
* Review dependencies regularly.
* Follow secure coding practices.
* Report potential vulnerabilities through appropriate internal channels.

Sensitive information should **never be included in public GitHub issues or repositories**.

## 📁 Repository Standards

Projects should maintain a clean and understandable repository structure.

Typical repositories may include:

```text
README.md
.gitignore
.env.example
CONTRIBUTING.md
CHANGELOG.md
docs/
src/
tests/
```

Each repository README should clearly explain:

* Project purpose
* Architecture
* Prerequisites
* Installation
* Environment configuration
* Development commands
* Build process
* Testing
* Deployment
* API documentation
* Repository ownership

## 🤝 Contributing

When contributing to an HGT repository:

1. Follow the project's coding standards and conventions.
2. Keep changes focused and maintainable.
3. Write meaningful commit messages.
4. Test changes before submitting them.
5. Provide a clear description of the changes.
6. Complete the required code review process.
7. Address review comments before merging.
8. Update relevant documentation when functionality changes.

Example commit messages:

```text
feat: add machine allocation workflow
fix: resolve quantity calculation issue
refactor: simplify approval workflow
docs: update API documentation
chore: update application configuration
```
